# ファイル構成と役割分担メモ

このドキュメントは、`LiteraryFragments` プロジェクトの主要なフロントエンド関連ファイル4つの役割と現在の実装状況をまとめたものです。

---

## 1. `index.html`

### 役割
WebViewで表示される画面の骨格（スケルトン）を定義するファイル。
画面に表示される全ての静的な要素（テキスト表示エリア、ボタンなど）は、このファイルでHTMLタグとして定義されています。
また、`style.css`（デザイン）と`main.js`（動き）を読み込む役割も担います。

### 現状と主要機能
- **基本構造**: HTML5で記述されており、`viewport`設定によりモバイル端末での表示に最適化されています（ズーム不可）。
- **要素**:
    - 名言を表示するメインのコンテナ (`quote-container`)
    - 初回起動時にスワイプ操作を促すガイド (`swipe-guide`)
    - 名言本文を表示するエリア (`#quote-text`)
    - 出典（作品名・著者名）を表示するエリア (`#source-area`)
    - 画面下部のナビゲーションバー (`bottom-bar`) と、その中のSVGアイコン付きボタン群。
- **外部ファイル**:
    - Google Fonts (`Montserrat`, `Open Sans`) を読み込んで、アプリ全体のフォントを指定。
    - `style.css` と `main.js` を読み込み。
- **インラインスタイル**:
    - スワイプガイドの矢印が呼吸するように動くアニメーション (`@keyframes float-left/right`) や、波紋が広がるアニメーション (`@keyframes ripple`) が直接記述されています。

## 2. `style.css`

### 役割
`index.html`で定義された要素の見た目（デザイン）を定義するファイル。
レイアウト、配色、フォントサイズ、アニメーションなど、アプリの視覚的な部分を全て担当します。

### 現状と主要機能
- **テーマ対応**:
    - CSS変数 (`:root` 内の `--bg-color` など）を使ってカラーテーマを管理。
    - `html[data-theme="dark"]` セレクタと `@media (prefers-color-scheme: dark)` を利用して、ライトモードとダークモードの両方に対応しています。
- **レイアウト**:
    - Flexboxを多用し、画面中央に名言を配置するレイアウトを構築。
    - `position: absolute` や `env(safe-area-inset-*)` を使用して、iPhoneのセーフエリア（ノッチや下部バー）を考慮した配置を実現。
- **アニメーション**:
    - 名言や出典が表示される際のフェードインアニメーション (`.fade-in`) を定義。現在は透明度 (`opacity`) の変化のみで、シンプルな演出になっています。
- **インタラクション**:
    - ボタンが押されたとき (`:active`) に少し小さくなるなど、ユーザー操作に対する視覚的なフィードバックを定義。
    - `user-select: none;` で多くの要素のテキスト選択を禁止しつつ、名言部分など必要な箇所だけ選択可能に上書きしています。
- **デザイン**:
    - 下部ナビゲーションバーにすりガラス効果 (`backdrop-filter: blur(...)`) を適用。
    - 検索キーワードに一致した単語をハイライト表示するための `.highlight-word` スタイルを定義。

## 3. `main.js`

### 役割
WebView内部での動的な処理やユーザーインタラクションを担当するファイル。
ボタンのタップ、スワイプなどの操作を検知し、画面表示を書き換えたり、Swift側のネイティブコードと連携したりします。

### 現状と主要機能
- **名言の表示処理 (`displayQuoteWithFade`)**:
    - Swiftから受け取った名言データをHTMLに反映させる中心的な関数。
    - 名言を単語ごとに `<span>` タグで分割し、単語ごとのタップ操作を可能にしています。
    - 検索キーワードが含まれていれば、該当単語にハイライトスタイルを適用します。
    - フェードインアニメーションを開始させます。
- **イベントリスナー (`setupEventListeners`)**:
    - 画面下部のボタンがタップされたら、`callSwift` を経由してSwift側の機能を呼び出します（設定画面表示、お気に入り登録など）。
    - 画面のスワイプを検知 (`touchstart`, `touchend`) して、次の名言や前の名言をリクエストします。
    - 単語の長押し (`touchstart` + `setTimeout`) やテキスト選択 (`selectionchange`) を検知して、ネイティブの翻訳機能を呼び出します。
- **Swiftとの連携**:
    - `callSwift` というヘルパー関数を用意し、`window.webkit.messageHandlers` を使ってSwift側にメッセージを送信します。
    - これにより、JS側でのイベントをきっかけに、ネイティブ機能（ハプティクス、音声読み上げ、画面遷移など）を起動できます。

## 4. `ContentView.swift`

### 役割
アプリのネイティブ部分の起点となるファイル。
`SwiftUI`で書かれており、WebView (`WKWebView`) を画面に表示するためのコンテナとして機能します。
アプリ全体の状態管理や、WebView(JS)とネイティブ機能との間の橋渡し役を担う、最も重要なコントローラーです。

### 現状と主要機能
- **WebViewの管理**:
    - `WebView` (UIViewRepresentable) を通じて `WKWebView` を生成・管理。
    - `WebView.Coordinator` が、JSからのメッセージ受信 (`WKScriptMessageHandler`) や、ネイティブ側からのJS実行を担当します。
- **状態管理**:
    - `QuoteDatabase` (API通信)、`QuoteStorage` (お気に入り/履歴の永続化)、`TicketManager` (課金チケット管理)、`LanguageManager` (多言語UI管理) など、アプリのコアロジックを持つクラス群を管理しています。
- **ネイティブUIの表示**:
    - 設定、お気に入り、AI解説などの画面を `.sheet` や `.fullScreenCover` を使ってモーダル表示します。
    - オンボーディング画面もここで管理されています。
- **JSとの連携（Coordinator内）**:
    - **受信**: JSからのメッセージ (`showSettings`, `speakText` など) を受け取り、`showingSettings = true` のようにStateを更新してUIを表示したり、`AVFoundation`で音声を再生したりします。
    - **送信**: `fetchRandomQuote` などで取得した名言データを `webView.evaluateJavaScript(...)` を使ってJSの `displayQuoteWithFade` 関数に渡し、画面を更新させます。
    - 名言を切り替える際の「ルーレット」アニメーションのロジックもここに実装されています。
